# Nadeck Bot

Telegram-бот поддержки. Это тонкий транспорт: сам он не хранит базу знаний — каждое сообщение пересылается на backend (`POST /api/chat`), тот же эндпоинт, что использует AI-виджет на сайте. Поэтому база знаний (FAQ + каталог товаров), промпт и модель для Q&A всегда одни и те же для обоих каналов. Бот отвечает только на обращения — сам он ничего не пишет и никаких сообщений по расписанию не рассылает.

FAQ-парсинг (сборка базы знаний из HTML-экспортов) живёт в backend'е — см. `../nadeck-backend/scripts/parseFaq.ts`.

## Как это работает

### Вопросы (личка и группы)

На каждое сообщение бот шлёт POST на `${BACKEND_URL}/api/chat` с текстом вопроса и историей переписки этого чата (в памяти процесса, до 10 последних пар вопрос-ответ), получает готовый ответ и пересылает его в Telegram.

В группах бот отвечает **всем участникам, кроме админов группы** (список админов кешируется на 10 минут через `getChatAdministrators`). Если сообщение адресовано боту через `@username`, упоминание вырезается перед отправкой на backend — это чисто косметическая правка.

Все диалоги логируются в `data/logs/conversations.jsonl` (вопрос, ответ) — для контроля качества.

### Список групп

Список групп бот собирает сам (`apps/nadeck-bot/src/groupStore.ts`): у Telegram Bot API нет метода "покажи все чаты, где я состою", поэтому бот запоминает id группы, как только его туда добавляют (событие `my_chat_member`), и убирает при удалении/кике. Список хранится в `data/groups.json` (в docker-compose это volume, переживает рестарт контейнера) — настраивать вручную ничего не нужно, достаточно добавить бота в группу. Сам по себе список ничего не рассылает — он просто фиксирует, где бот состоит.

## Запуск

```bash
npm install
# .env общий для всей монорепы — лежит в корне репозитория (см. ../../.env.example)
# backend должен быть запущен и доступен по BACKEND_URL (по умолчанию http://localhost:3001)
npm run bot
```

## Настройка

Через корневой `.env` репозитория (не свой файл в этой папке):
- `TELEGRAM_BOT_TOKEN` — токен бота.
- `BACKEND_URL` — адрес backend'а (по умолчанию `http://localhost:3001`; в docker-compose — `http://backend:3001`).

Своего ключа OpenAI боту не нужно: модель, температура, промпт и база знаний живут в backend'е (`../nadeck-backend/src/chat/chat.service.ts`, `../nadeck-backend/scripts/parseFaq.ts`).
