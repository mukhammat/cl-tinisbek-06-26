# Nadeck Bot

Telegram-бот поддержки, отвечающий на вопросы по базе знаний Nadeck (полная база в системном промпте + OpenAI).

## Как это работает

1. Карточки FAQ (HTML-экспорт или JSON) лежат в `data/faq/*.html` / `data/faq/*.json`.
2. `npm run parse-faq` — парсит все файлы в `data/faq.json` (вопрос/ответ/источник).
3. `npm run bot` — запускает Telegram-бота: вся база знаний целиком передаётся модели в системном промпте на каждый запрос. Модель не ищет точное совпадение вопроса, а рассуждает по базе как консультант — может связать вопрос с несколькими карточками, перефразировать, при нехватке данных опереться на общие знания о пептидах (явно обозначая, что это не из базы клиента).

Все диалоги логируются в `data/logs/conversations.jsonl` (вопрос, ответ) — для контроля качества.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить TELEGRAM_BOT_TOKEN и OPENAI_API_KEY
npm run parse-faq
npm run bot
```

## Добавление новых карточек

Положи новый HTML-экспорт (такой же формат, как `Nadeck_FAQ_new_zero_13_cards.html`) или JSON-файл (массив `{question, answer}`) в `data/faq/` и заново прогони:

```bash
npm run parse-faq
```

Бот подхватит новую базу при следующем запуске (`npm run bot`) — она читается один раз при старте, не на каждое сообщение.

## Настройка

Через `.env`:
- `OPENAI_CHAT_MODEL` — модель для генерации ответов (по умолчанию `gpt-4o-mini`).

## Важно про размер базы

База (417 карточек) — это ~70-80 тысяч токенов в системном промпте на каждый запрос. Это дороже и медленнее, чем поиск по top-K (как было раньше), но проще и не режет ответы по строгому совпадению вопроса. Если база вырастет в разы (тысячи карточек) и перестанет помещаться в контекст модели или расходы станут не окупаться, стоит вернуться к retrieval-подходу (top-K по embeddings) — раньше это уже было реализовано и может быть восстановлено при необходимости.
